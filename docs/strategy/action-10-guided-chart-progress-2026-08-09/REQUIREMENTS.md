# Guided Chart Progress and Learning — Product Requirements

Date: August 9, 2026
Revised: August 14, 2026
Product owner: Jim
Classification: UI/UX enhancement with small local presentation-state needs
Rules-engine impact: None

## 1. Product intent

Help a person recognize that a saved observation has become useful chart data and learn one relevant product/charting concept at a time without interrupting daily entry.

Well Within already has a strong engine, a current-cycle summary, field guidance, Help, and history. This action does not add more interpretation. It improves recognition, sequencing, and discoverability around those existing capabilities.

## 2. Revised recommendation

Build three bounded additions:

1. **First-save confirmation** — a calm one-time sheet after the first qualifying save.
2. **Contextual chart lesson** — one optional, finite app-literacy lesson below Today's Observation when an unseen lesson is relevant.
3. **First-completed-chart acknowledgement** — a compact, one-time History moment that routes to the existing completed chart.

Do not add a Learn tab, content feed, rotating tip carousel, course, streak, or permanent lesson card. Do not automatically repeat lessons in every cycle.

## 3. Locked existing-UI contract

Existing product UI is a source asset, not redesign territory for this action.

### 3.1 Calendar screen order

Preserve the current order and behavior:

1. Well Within header and Settings action;
2. Calendar / Cycle History segmented toggle;
3. current StatusBanner;
4. Catch Up card when eligible;
5. app-issue feedback link;
6. complete CalendarGrid;
7. TodayEntryCard;
8. **new contextual lesson section, only when eligible**;
9. existing Need help understanding your chart? card.

### 3.2 Components that must remain intact

- The calendar always renders the complete month grid generated by CalendarGrid, including every week required by that month.
- Preserve month navigation, weekday headers, cell dimensions, colors, markers, today outline, Peak outline, P+ labels, future-day treatment, legend, legend key, and day-tap behavior.
- Preserve StatusBanner structure, copy selection, actions, tone, and hierarchy.
- Preserve Catch Up, feedback, TodayEntryCard, Help, segmented navigation, Cycle Summary, and Cycle cards.
- Preserve current entry/save behavior and required tap count.

### 3.3 Permitted visual adjustment

Only the new component and directly surrounding layout may change:

- add the new section below Today's Observation;
- use existing spacing, typography, color, line-icon, border, and target-size tokens;
- make a small margin adjustment immediately above/below the new section if screenshot QA shows crowding;
- allow normal scrolling to reveal the new section.

This action does not authorize compressing the calendar, removing rows, moving existing sections, restyling existing cards, changing navigation, or “cleaning up” unrelated UI.

## 4. Product principles

### 4.1 Learning follows action

Education appears only after the relevant product action or state exists. It never blocks or precedes Save.

### 4.2 One useful idea

Show at most one contextual lesson. Do not stack recommendations or replace a dismissed lesson immediately.

### 4.3 Standalone, not repetitive

The current summary answers what the chart says now and what the user should do next. A lesson teaches a durable skill about recording or reading the app. Neither surface depends on the other.

### 4.4 Observational, not predictive

Lessons may explain what the user recorded and how Well Within displays it. They do not forecast, diagnose, confirm ovulation, identify safe/unsafe days, or introduce a new fertility state.

### 4.5 Earned, not gamified

Recognize a save or completed chart without scores, streaks, grades, confetti, progress rings, or missed-day shame.

### 4.6 Finite and user-controlled

Lessons are consumed once per content version, can be dismissed individually, can be hidden globally, and do not restart each cycle.

## 5. Architecture placement

| Layer | Responsibility | Impact |
| --- | --- | --- |
| core/rulesEngine | Existing calculation, summary, explanation targets, and education exports remain authoritative | **No changes** |
| apps/mobile presentation | Choose among approved lessons using existing product state; render confirmation and lesson surfaces | New UI components and a thin UI-only selector |
| Local presentation preferences | Store whether chart tips are enabled and which lesson/version IDs were viewed or dismissed | Device-local UI state only |
| Storage/sync | Existing observations and optional sync | No schema or semantic changes |
| Analytics | Not included | No new SDK or sensitive event collection |

### 5.1 UI selector may

- detect a successful qualifying save;
- count distinct saved non-missing dates for acknowledgement copy only;
- detect existing observations such as Dry, mucus, Not observed, or multiple same-day observations;
- use existing cycle-history availability;
- read the current explanationTarget only to avoid duplicate topics;
- read/write lesson IDs and content versions in local presentation preferences.

### 5.2 UI selector must not

- recalculate mucus rank, Peak, P+ days, possible-pattern boundaries, cycle boundaries, or completeness;
- inspect observations to invent an interpretation;
- change the current summary or Help destination;
- claim that a number of observed days or lessons has clinical meaning.

## 6. Education sourcing and review

The [Education Content Model](EDUCATION_CONTENT_MODEL.md) is normative.

Shipping lessons use, in order:

1. existing reviewed Well Within education/presentation copy;
2. current versioned repository specifications and provenance records;
3. authoritative method-owner/public institutional or peer-reviewed primary sources for alignment and risk boundaries;
4. documented qualified reviewer decisions for any new method-level explanation.

Public Creighton/FertilityCare material may inform internal review, but must not be copied, visually imitated, or presented as official instruction. User-facing language remains brand-neutral and must not imply affiliation or certification.

No lesson is sourced from generative AI, a competitor, a scraped article, a community anecdote treated as fact, or a live content request.

## 7. Surface roles and duplicate prevention

| Surface | Required job |
| --- | --- |
| StatusBanner | Current patient-specific chart state, limitation, explanation target, and next action |
| New chart lesson | Durable product mechanic or reading skill useful beyond today's summary |
| Help | Full browsable reference and lesson archive |
| Confirmation/milestone | Acknowledge a saved action or available chart; no teaching burden |

Every lesson has a stable topicId. Existing summary explanation targets map to topic IDs. If the active summary already offers an explanation for the same topic, the lesson selector must choose a different eligible lesson or show nothing.

Content QA must compare the proposed lesson with the active summary's headline, status line, supporting context, guidance, limitation, and action label. Paraphrasing the same message still counts as duplication.

## 8. Primary user flow

1. User saves the first qualifying intentional observation through the unchanged entry flow.
2. Existing persistence succeeds and the existing navigation returns the user to Calendar.
3. A one-time orientation sheet appears over Calendar and says Your chart has started.
4. The sheet explains that relevant chart tips appear below Today's Observation as the user continues charting.
5. Got it or standard sheet dismissal closes the message and leaves the user on Calendar.
6. User scrolls through the current full calendar and Today's Observation.
7. If an approved unseen topic is relevant and non-duplicative, one contextual lesson appears.
8. User may open it, dismiss that topic, hide all chart tips, or ignore it.
9. Opening the lesson shows a 30–60 second explanation and an exact product-native example.
10. Returning restores the Calendar scroll position.
11. Once all eligible lessons are viewed/dismissed—or chart tips are hidden—the section disappears; existing Help remains.
12. A first completed chart may receive one acknowledgement in History and then returns to normal History UI.

## 9. Required states

### GP-0 — No qualifying observation

- No confirmation or contextual lesson.
- Existing empty-state summary, Calendar, Today, and Help remain unchanged.

### GP-1 — First qualifying save

**Confirmation**

- Eyebrow: FIRST OBSERVATION SAVED
- Title: Your chart has started
- Body: Your observation is saved. As you keep charting, short tips will appear below Today's Observation to help you understand what you're seeing.
- Action: Got it

If the saved date is today, Today's observation is permitted. If it is a past date, use Your observation.

### GP-2 — Eligible unseen lesson

- Render one new section below Today's Observation.
- Section label: LEARN FROM YOUR CHART
- Lesson title comes from the approved catalog.
- A trailing More action provides lesson controls.
- No numeric progress or claim about how many lessons remain.

### GP-3 — Current summary owns the topic

- Do not show a lesson that matches the active summary topic.
- Select another eligible topic only if it is independently valuable.
- Otherwise render no lesson section.

### GP-4 — Lesson viewed or dismissed

- Mark that lesson/version viewed or dismissed locally.
- Do not replace it immediately.
- Return to Calendar at the prior scroll position.
- It remains deliberately discoverable in Understanding Your Chart > Chart tips.

### GP-5 — Library exhausted or tips hidden

- Remove the new lesson section entirely.
- Preserve current summary, full calendar, Today, and Help unchanged.
- Do not restart at a new cycle.
- Show chart tips on Calendar in Help can reverse the global hide choice.

### GP-6 — First completed chart

- Trigger only from existing History availability.
- Show one compact acknowledgement without changing Cycle Summary or Cycle cards.
- Title: Your first completed chart is ready to review
- Body: Look back at the observations and retrospective markers saved in this chart.
- Action: Review this chart
- After view/dismissal, retain the normal current History UI.

## 10. Version-one lesson catalog

| Lesson ID | Display title | Trigger | Source | Duplicate suppression |
| --- | --- | --- | --- | --- |
| observation-on-calendar | How your observation appears on the calendar | First qualifying save | Current calendar presentation and color guide | None normally |
| dry-not-observed-open | Dry, Not observed, and no entry are different | First Dry or Not observed record | Current missing/status/Help contracts | Hide while summary is explaining a missing/incomplete topic |
| sensation-and-appearance | How sensation and appearance work together | First non-Dry mucus observation | Existing engine-owned Help copy | Hide if current status specifically requires completing sensation/appearance |
| multiple-observations | What happens when you record more than one observation | First multi-observation date | Existing Entry and Help copy | Hide while current status focuses an incomplete observation |
| completed-chart-review | What you can review in a completed chart | First completed chart | Existing History/Cycle Detail copy | History only; never duplicates Calendar summary |

Peak-type versus Peak Day, P+ markers, spotting/brown layering, special contexts, and comparison education remain phase-two candidates pending direct user evidence and required review. Existing summary-to-Help explanations continue to cover current-state questions.

## 11. Interaction requirements

### 11.1 First-save confirmation

- Present only after Save succeeds.
- Let the existing flow return to Calendar before presenting the sheet.
- Present once per local profile context.
- Never present for missing/Not observed save, edit, imported/restored/synced entry, or automatic state restoration.
- Do not delay persistence or sync.
- Use one Got it action; do not present two actions that lead to the same place.
- Got it, swipe dismissal, and accessibility escape all close the sheet in place on Calendar.
- Do not auto-scroll after dismissal.

### 11.2 Lesson section

- Place below Today's Observation and before existing Help.
- Use a compact list/divider treatment consistent with existing UI.
- Show at most one lesson.
- The full month calendar remains intact above it.
- Existing summary/Catch Up retains urgency and visual priority.
- Preserve scroll position after lesson close.

### 11.3 Lesson detail

- Use a standard bottom sheet or pushed detail consistent with current navigation.
- Target 30–60 seconds.
- One title, one concise explanation, at most one deterministic product example, one return action, and an optional deeper Help link.
- Minimum 44-point targets and ordered VoiceOver focus.
- Miniature chart examples require text labels; color cannot carry meaning alone.

### 11.4 Controls

Trailing More action:

- Not relevant to me
- Hide chart tips
- Cancel

Global hide is reversible from Understanding Your Chart > Chart tips. It affects only contextual lesson cards, never safety/status explanations.

### 11.5 Motion

- Standard native sheet transition.
- No confetti, bounce, haptic by default, looping animation, or ornamental progress indicator.
- Respect Reduce Motion.

## 12. Exhaustion, reset, and content updates

- Viewed/dismissed lessons do not automatically repeat in later cycles.
- A new cycle does not reset education.
- If content changes materially, increment its content version.
- A new version does not automatically resurface unless product explicitly marks it eligible and the change provides new user value.
- Users can always browse completed/dismissed lessons in Help.
- If no lesson is eligible, the Calendar should look exactly as it does today.

## 13. Accessibility and privacy

- Announce section heading, lesson title, and More action in logical order.
- Larger text may expand without overlapping existing Calendar/Today/Help content.
- Sheet focus moves to the lesson title and returns to the invoking row.
- No automatic advancement.
- No network request, third-party content service, AI generation, or analytics.
- Preferences contain IDs/versions only; no copied observation values.
- No change to export, backup, sync, deletion, or account semantics.

## 14. Edge cases

| Case | Required behavior |
| --- | --- |
| Existing summary owns the same topic | Suppress duplicate lesson; show another eligible lesson or none |
| First saved observation is a past date | Use Your observation, not Today's observation |
| Multiple same-day observations | Count the date once for acknowledgement; multi-observation lesson may become eligible |
| Saved Not observed/missing day | Does not trigger first-save acknowledgement; may make the distinctions lesson eligible later |
| Imported/restored/synced history | No first-save acknowledgement; unseen app-literacy lesson may appear only in a normal later session |
| Catch Up or review-recommended status active | Existing action stays primary; lesson remains below Today and may be suppressed |
| Lesson dismissed | Do not immediately substitute another |
| All lessons viewed | Remove lesson section; do not cycle back to lesson one |
| User hides tips | Remove contextual lesson section until re-enabled in Help |
| Content version changes | Preserve prior state unless explicit product review authorizes resurfacing |
| Reduced Motion | Use standard screen change only |

## 15. Acceptance criteria

### Existing UI preservation

- [ ] Mockups and implementation show the complete month calendar, never a representative single row.
- [ ] Existing screen order and existing component content/behavior remain unchanged.
- [ ] Calendar rows, cells, colors, markers, legend, summary, Catch Up, feedback, Today, Help, History summary, and cycle cards are preserved.
- [ ] Only the new surfaces and directly adjacent spacing differ.

### Functional

- [ ] First-save acknowledgement appears only after a successful qualifying save.
- [ ] Lesson selection uses existing presentation state and local lesson preferences only.
- [ ] No rules-engine, schema, sync, export, or summary behavior changes.
- [ ] The selector suppresses active-summary topic duplication.
- [ ] Viewed/dismissed lessons do not repeat each cycle.
- [ ] Exhausted/hidden state renders no lesson section.
- [ ] Global hide is reversible from Help.

### Content

- [ ] Every lesson has a source record, topic ID, content version, trigger, and required reviewer approval.
- [ ] Lesson copy remains useful without the current summary.
- [ ] Summary remains sufficient without the lesson.
- [ ] No protected method text/art is reproduced and no affiliation is implied.
- [ ] Version one is limited to the approved app-literacy catalog.

### UX/accessibility/privacy

- [ ] Save requires the same number of taps as today.
- [ ] One lesson maximum and no streak/progress score.
- [ ] Returning from a lesson restores Calendar position.
- [ ] VoiceOver, Dynamic Type, Reduce Motion, and 44-point targets pass.
- [ ] No network, third-party SDK, analytics, or sensitive-data duplication.

## 16. Suggested implementation tickets

### Ticket A — Lesson catalog and source ledger

- Define typed IDs, versions, triggers, topic mappings, exact copy, destinations, and approvals.
- Reuse existing education copy where possible.
- Hold any method-level addition without required review.

### Ticket B — UI-only eligibility selector

- Select one unseen eligible lesson.
- Apply summary-topic suppression.
- Test no-entry, Dry, Not observed, mucus, multi-observation, completed-chart, dismissal, exhaustion, global hide, and content-version cases.

### Ticket C — First-save confirmation

- Add the one-time post-save sheet.
- Cover current/past dates, edits, missing, imports, restores, and sync suppression.

### Ticket D — Contextual lesson and controls

- Add the section below the unchanged Today's Observation.
- Add detail presentation, More action, and scroll restoration.
- Add Chart tips archive/re-enable control inside existing Help.

### Ticket E — First completed-chart acknowledgement

- Add one bounded History acknowledgement using existing completion availability.
- Do not change current summary or Cycle cards.

### Ticket F — Source-faithful QA

- Screenshot compare the full Calendar and History before/after.
- Verify no existing element was removed, compressed, reordered, or restyled.
- Complete content, accessibility, privacy, and product-boundary review.

## 17. Explicitly out of scope

- Rules-engine changes or new interpretation targets.
- New medical, diagnostic, timing, pregnancy, or avoidance guidance.
- Formal Creighton/FertilityCare instruction or affiliation.
- Learn tab, course, quiz, feed, recommendation service, or remote CMS.
- Automatic lesson recycling, streaks, scores, badges, or completion percentage.
- Notification strategy, analytics, experimentation SDKs, or production release work.
